Mission: Failure classification, proven cause and required correction scope.
Definition: DRWA-defined local checking instructions; no upstream concept is renamed.
Status: compact audit repair; any new manifest requires owner rebind.
Authority: the installed contract and latest explicit owner instruction control.
Execution: one configured read-only Claude call.
Independence: all producer-invoked models are self-checks; no acceptance authority.
Reliability: no instruction length or finite evaluation proves absence of every future error.
Evidence: this manual defines obligations; executed coverage is only in retained results.
Selection: only when an actual failure is recorded.
Basis: AGENTS.md §8; development prompt §8.7.
Source identities are resolved at runtime; this file does not duplicate bound hashes.
Apply the shared criterion protocol in 00_common.md to every relevant numbered question below.
Review scenarios below are specifications; they are not claims of executed paired fixtures.
Missing execution, missing source and unresolved ambiguity stay visible as open work.
A clean model response is neither a stage acceptance nor a replacement for script evidence.

# Checks

### FAILURE_CLASS-001 Observed event
Question: Is the actual failed invocation and outcome identified?
Primary witness: Exact command, exit and retained raw output.
Counterexample: Classify a failure from a paraphrased complaint only.

### FAILURE_CLASS-002 Product defect
Question: Is wrong product behavior established against the specification?
Primary witness: Approved requirement and executed violation.
Counterexample: Call a quoting mistake a product bug.

### FAILURE_CLASS-003 Self-inflicted defect
Question: Is an agent's wrong command, edit or claim the cause?
Primary witness: Before/after agent action and source evidence.
Counterexample: Blame an external environment for an invented input.

### FAILURE_CLASS-004 Environment event
Question: Is the fault in the execution environment rather than product semantics?
Primary witness: Bounded environment diagnostic and invocation.
Counterexample: Treat a sandbox denial as product nonconformance.

### FAILURE_CLASS-005 Invocation exception
Question: Did the invocation fail before work with no derived fact or side effect?
Primary witness: Raw invocation and unchanged artifacts.
Counterexample: Call a partially executed script an invocation error.

### FAILURE_CLASS-006 Compile exception
Question: Does the temporary compile-only failure meet every contract condition?
Primary witness: Uncommitted isolated edit and compile record.
Counterexample: Treat a shared source compile failure as an exception.

### FAILURE_CLASS-007 Side-effect boundary
Question: Are file, state, process and network effects independently considered?
Primary witness: Changed artifacts and operation scope.
Counterexample: Assume nonzero exit means nothing changed.

### FAILURE_CLASS-008 Derived facts
Question: Was any later expectation or decision based on the failed output?
Primary witness: Subsequent claims and consumer records.
Counterexample: Call a failure harmless after using its output as an oracle.

### FAILURE_CLASS-009 Root-cause proof
Question: Does the cause have an exact source or byte-level witness?
Primary witness: Cause-bearing line and original symptom.
Counterexample: Name missing cache without checking the cache path.

### FAILURE_CLASS-010 Symptom distinction
Question: Is the reported symptom separated from the demonstrated mechanism?
Primary witness: Error output and causal source trace.
Counterexample: Treat missing output as proof of the underlying cause.

### FAILURE_CLASS-011 Surface sweep
Question: Are every same-pattern producer and consumer enumerated?
Primary witness: Scripts, fixtures, manifests and inputs.
Counterexample: Fix one quoting occurrence while retaining another.

### FAILURE_CLASS-012 Owning layer
Question: Does the correction address the layer that introduced the defect?
Primary witness: Producer source and affected consumers.
Counterexample: Patch product logic to hide a capture-tool defect.

### FAILURE_CLASS-013 Correction inventory
Question: Does the record name every decision affected by the wrong claim?
Primary witness: Prior claim and downstream use list.
Counterexample: Correct a hash without revisiting decisions made from it.

### FAILURE_CLASS-014 Focused proof
Question: Is the correction proven by the same or stricter bounded case?
Primary witness: Retained post-fix reproduction.
Counterexample: Declare a fix from visual inspection only.

### FAILURE_CLASS-015 Expensive rerun
Question: Did a bounded smoke prove the exact command first?
Primary witness: Smoke command and its status.
Counterexample: Restart a full suite after a quoting failure.

### FAILURE_CLASS-016 Recurrence identity
Question: Does recurrence refer to the same demonstrated root cause?
Primary witness: Failure records and correction proof.
Counterexample: Merge unrelated symptoms as the same recurrence.

### FAILURE_CLASS-017 Recurrence ruling
Question: Is a repeated root cause after a proven fix returned to the owner?
Primary witness: Previous fix proof and current cause.
Counterexample: Retry indefinitely under a new failure label.

### FAILURE_CLASS-018 Live surface count
Question: Are live or irreversible occurrences counted under the stricter rule?
Primary witness: Operation target and retained occurrences.
Counterexample: Retry an ambiguous transaction as a local invocation error.

### FAILURE_CLASS-019 Ambiguous transaction
Question: Is ambiguous acceptance left unresolved without resubmission?
Primary witness: Raw submission result and owner ruling.
Counterexample: Retry because no final receipt was observed.

### FAILURE_CLASS-020 Programme count
Question: Are cumulative relevant failures read from the bound register?
Primary witness: Register identity and applicable entries.
Counterexample: Reset counts at the start of a new session.

### FAILURE_CLASS-021 Register protection
Question: Is the register left owner-only?
Primary witness: Bound register and proposed correction.
Counterexample: Edit the register to remove the blocking occurrence.

### FAILURE_CLASS-022 Evidence retention
Question: Are original failed outputs retained with exact identities?
Primary witness: Failure record and capture artifacts.
Counterexample: Overwrite the failed run with successful output.

### FAILURE_CLASS-023 Repair authority
Question: Is a correction within already granted reversible scope?
Primary witness: Owner instruction and edit boundary.
Counterexample: Seek a new grant for an in-scope typo repair.

### FAILURE_CLASS-024 Boundary expansion
Question: Is a newly required path reported before broader mutation?
Primary witness: Current boundary and downstream affected file.
Counterexample: Edit another package silently while fixing the owning file.

### FAILURE_CLASS-025 Proof versus credit
Question: Is failure repair kept distinct from product qualification?
Primary witness: Evidence labels and acceptance rules.
Counterexample: Award qualification credit for fixing a tooling invocation.

### FAILURE_CLASS-026 Partial execution
Question: Are partial writes or publication states reconciled truthfully?
Primary witness: Before/after bytes and incomplete output directory.
Counterexample: Erase the partial attempt to simplify history.

### FAILURE_CLASS-027 Concurrent change
Question: Is a concurrent writer distinguished from agent-owned bytes?
Primary witness: Retained identities and exact changed artifacts.
Counterexample: Overwrite another actor's edit during recovery.

### FAILURE_CLASS-028 Operational script
Question: Does an operational procedure use a named reviewed script?
Primary witness: Script identity and argument manifest.
Counterexample: Assemble a new ad-hoc launch sequence after each failure.

### FAILURE_CLASS-029 Unknown cause
Question: Is an unproven cause left UNKNOWN with the smallest missing input?
Primary witness: Known symptom and missing source witness.
Counterexample: Invent a confident diagnosis to continue execution.

### FAILURE_CLASS-030 Class consistency
Question: Do class, cause, side effects and required response agree?
Primary witness: Complete failure record and contract rules.
Counterexample: Use the invocation exemption while acknowledging a write.
